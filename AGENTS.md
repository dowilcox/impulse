# Repository Guidelines

`CLAUDE.md` is the detailed guide to this repository; this file is the short version for any coding agent.

## Project Structure

Impulse is a Mac-first terminal IDE written in Swift (AppKit + SwiftUI), with the terminal emulation core in Rust.

- `impulse-macos/` — the Swift package. `Sources/ImpulseApp` is the app; `Sources/ImpulseKit` holds Foundation-only logic (headless-testable); `Sources/ImpulseGit` wraps a vendored libgit2 (reads) plus the `git` CLI (writes); `Sources/ImpulseLSP` is the language-server client; `Sources/ImpulseProtocol` is the control-socket protocol and the MCP server that `Sources/ImpulseCLI` (`impulse`, `impulse mcp`) runs. `web/` holds the Monaco editor glue (the review is native).
- `impulse-terminal/` — Rust terminal emulation on `alacritty_terminal` (PTY, grid, OSC 133/7/9/6973 scanning, command blocks, history).
- `impulse-ffi/` — the C FFI over `impulse-terminal`, linked into the app as a static library.
- `impulse-kit/` (rust branch) — the full-Rust migration's port of ImpulseKit, checked against the Swift tests' golden fixtures; see `docs/plans/rust-migration.md`.
- `impulse-git/` (rust branch) — the git layer in Rust (libgit2 reads, git CLI writes).
- `impulse-lsp/` (rust branch) — the language-server client for the Rust app.
- `impulse-protocol/` and `impulse-cli/` (rust branch) — the control protocol, MCP server and `impulse` CLI in Rust.
- `impulse-app/` (rust branch): the whole app on GPUI + GPUI Kit (pinned exactly) for macOS and Linux: workspaces and tabs, terminal and input bar, editor tabs with language servers (shared app-wide), Review and History, git panels, tasks, agents and the control socket; what still differs from the Swift app is listed in `docs/plans/rust-migration.md`.
- `vendor/` — Monaco, monaco-vim, fonts, highlight.js and lucide (refresh with the `scripts/vendor-*.sh` scripts; never hand-edit).
- `docs/` — the user documentation, one Markdown page per area. Its screenshots (`docs/images/`) are generated by `scripts/docs/capture.py`; update the docs when you change user-facing behavior.

## Build and Test

Use the scripts; don't replicate their steps by hand.

- `./impulse-macos/build.sh --dev` — build `dist/Impulse Dev.app` (runs alongside the release app). On Linux (rust branch) it builds the Rust app and CLI in debug mode instead (`target/debug/impulse-app`), and without `--dev` runs `scripts/package-linux.sh`.
- `impulse-macos/swiftw build` / `impulse-macos/swiftw test` — build or test the Swift package with the flags the local toolchain needs.
- `cargo test -p impulse-terminal`, `cargo test -p impulse-kit`, `cargo test -p impulse-git`, `cargo test -p impulse-lsp`, `cargo test -p impulse-protocol -p impulse-cli`, `cargo fmt`, `cargo clippy` — Rust core.
- `python3 scripts/smoke/run.py` — smoke checks of the dev build (editor, shells, CLI, agents, language servers, tasks, session restore), headless; run before a release. The opencode scenario needs `node`. `IMPULSE_SNAPSHOT_APP=target/debug/impulse-app` (the default on Linux, under Xvfb; on the Mac build it with `--features impulse-app/snapshot`) runs them, and `scripts/docs/capture.py`, against the Rust app.
- `scripts/check-macos.sh` (rust branch) — `cargo check` of the Rust app for macOS from Linux, so Mac-only code compiles; nothing is linked or run.
- `scripts/package-linux.sh` (rust branch): release build of the Rust app and CLI, packaged into `dist/` as a tarball and a `.deb` (icons and fonts in `share/impulse/`, found by `impulse-app/src/resources.rs`).
- `./scripts/release.sh <version> [--push]` — the only release path.

## Conventions

- Swift types are `CamelCase`; keep new backend logic out of `Bridge/ImpulseCore.swift` and in the right library target.
- Golden fixtures under `impulse-macos/Tests/*/Fixtures` are the spec. Never regenerate them from Swift output; if behavior changes on purpose, edit the fixture in the same commit and say why. New git APIs use the real `git` CLI as the test oracle.
- Wrap new test files in `#if canImport(Testing)`.
- Keep `CLAUDE.md` and this file current: a change that adds, removes, renames or moves a feature, target, directory, script or file format updates them in the same commit.
- Commits are short, imperative, sentence case (`Add OSC 8 hyperlink support`); release commits are `Release vX.Y.Z`.
